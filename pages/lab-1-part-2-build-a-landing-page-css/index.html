Media query

Now for the tricky part! Shrink the width of your browser window all the way down! GASP! 💩

Most likely it did not resize well. We’ll deal with this using a single media query.

🚀Here’s how to start:

@media only screen and (max-width: 640px) {

}

Anything in this media query will only apply if the screen is fairly narrow. Don’t worry about it working on every single device - rather focus on it working in a more general fashion in a “mobile” width vs “desktop”. Flex-boxes will take care of things being responsive in most widths but you want to make sure that there is a mobile version where a few bigger site wide changes happen: rows into columns, nav links into hamburger menu.

⚠️⚠️⚠️ Add <meta name="viewport" content="width=device-width, initial-scale=1"> to the head section of your html. This tells the mobile browser to not pretend to be a real browser and use actual device pixels for width and allows you to test on mobile / in the Chrome mobile device mode.

Important Techniques

flex-direction: column;

🚀 Take some of your row flex boxes and simply convert them to columns. This works remarkably well for many cases. The input box and button, the links at the bottom, the highlight selections in the middle.

display: none;

This method can be very powerful. For your navbar the recommendation is to do this:

create 2 separate nav elements.

<nav class="desktop">

<nav class="mobile">

Then in your stylesheet you can do:

by default nav.mobile { display: none;}

and then in your @media query

switch which is displayed and which is hidden!

nav.mobile { display: flex;} & nav.desktop { display: none;}

This way you can toggle the display property on completely different sections of the site. You might have a completely different set of elements for the links section for instance. Toggle one off and the other on.

Speaking of CSS responding to clicks…

Notice that on most of these pages when you’re in the narrow responsive site if you click on the Hamburger Menu button an overlay menu comes up. This is done with javascript the world over. BUT it is possible to trick CSS into responding to clicks!

This is called the CSS Checkbox Hack, very clever.

You can implement this functionality in pure CSS. You can also play with CSS transitions for this to make the menu appear to slide or fade in. Caveat: CSS transitions don’t work if the element has display: none on it, but there are other ways to hide an element, opacity + height: 0px come to mind.

Automatic Testing (in beta)

We've provided a small test suite with this assignment. It doesn't grade you — it checks the structural things that are easy to forget: the viewport meta tag, semantic elements, a nav with links, flexbox layout, a mobile breakpoint, hover styles, and that you haven't snuck in any JavaScript. Run it from your project directory:

cd tests

npm install

npm run setup # one time only — downloads a browser to test with

npm run test

Terminal

These tests are written with Playwright, which drives a real browser — it's what we'll use for testing all term, so this is your first look at it. Try npm run test:ui to watch it work through your page one check at a time. This is a trial and we won't use it in grading. Your page is supposed to be creative, so a passing test doesn't mean it's good and a failing one doesn't mean it's broken — if it flags something you think is fine, tell us. Feedback welcome!
