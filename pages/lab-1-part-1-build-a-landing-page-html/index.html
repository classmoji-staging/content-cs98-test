Your assignment, should you choose to accept it, (not sure you have much choice there…) is to create a landing page.

A landing page, you say? Yes, you will be making a landing page based on a real page out there in the world. You will be mimicking the structure and style of a page but with your own content.

Focus on HTML foundations

Lay out the skeleton of a beautiful static landing page

PART 1: HTML

Dive Right In!

🚀 Start in the provided repo by Classm🍎ji. It will look like dartmouth-cs52/lab1-landingpage-yourgithubusername. Please do not work in your own repo — use the class provided repository only.

🚀 Open up your code editor and create an index.html and a style.css file in the root of the folder.

basic html page

empty style.css

🚀 Link your style.css file into the head of your html file. (no CSS allowed for the first part just set up the file)

📌 Use relative paths for everything you link — style.css and img/hero.jpg, not /style.css. That leading slash means “start at the root of the server”: it works once your site is hosted, but not when you open index.html straight off your disk — which is how the test suite opens it. Your page will look completely unstyled and the reason won't be obvious.

Outline

In HTML only, outline the main elements you envision for the page. Here’s some hints:

remember to use semantic elements that we discussed in class.

<nav> for the navbar (even though it is transparent).

<ul> unordered lists are often used for nav components, if you do it’ll help to get rid of the bullets using list-style-type: none; in your css later.

<footer> is a good tag to use for… footer things.

<div>, <span>, <a>, <h1>, <p> will all be useful.

<input>, and <button> for any form like elements.

Don’t worry about styling 💇 at this point. Just lay things out in an order that makes sense to you. BUT do think about how to label your structure. Use id and class as appropriate to differentiate your elements so that later you can style them. Remember this is structure you are describing.

Git Tags

🐙 To keep track of specific important changes in our repositories, we’re going to be using git tags. Tags are a way to give a specific git commit a name/label for easy retrieval later. Github uses tags to mark software release versions as well.

# first make sure you've committed your code

git commit -am "done with html layout stage"

# when you run git tag it will label the current latest commit

git tag html

# tags need to be pushed to github manually

git push origin --tags

Now you can take a break, we’ll learn some CSS in class, and you can come back and make this pretty in Lab 1 Part 2: Build a Landing Page CSS.

You Are Done with the HTML Part 1 of the lab! Now, don’t forget to host it.

Three ways to do it — pick one. Option A: render.com — connect your GitHub account and publish this repo as a static site. It has a decent free tier and it works with the private class repo. Option B: GitHub Pages — the same flow you already did in SA0, from this repo's Settings → Pages (check it's offered there; Pages on a private repo depends on the org plan). Option C: Cloudflare Pages — connect this repo from the Cloudflare dashboard and it redeploys on every push. Free, fast, and worth setting up now: we'll be diving into Cloudflare properly later in the term when we get to Workers and Durable Objects, so you'll already have the account. Whichever you pick, this is a separate site from the personal domain you set up in SA0 — don't overwrite that one. All three HOST your site on an internet connected server (ie. “in the cloud”) ☁️.
